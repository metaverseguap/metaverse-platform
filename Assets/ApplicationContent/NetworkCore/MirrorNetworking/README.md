# Mirror Networking
Модуль многопользовательского взаимодействия через библиотеку Mirror.

## NetworkManager
Основным компонентом библиотеки Mirror является `NetworkManager`. 
Данный класс отвечает за создание сети, отслеживание сетевых событий, подключение к другим сетям,
спавн сетевых объектов на сервере и клиентах и еще за множество сетевых функций. 
Оперировать всем функционалом данного компонента в рамках одного скрипта практически невозможно. 
Поэтому к данному классу применена декомпозиция, позволяющая, хоть немного, разделить ответственность данного класса.

`MVNetworkManager` является наследником `NetworkManager` и получает от него всю полноту власти, но ограниченную область ответственности.
Данный компонент является объектом, создающим и настраивающим сетевое поведение. Наличие данного компонента в сцене определяет, является ли сцена сетевой.
Поэтому у данного компонента есть статические методы `MVNetworkManager#IsOnline` и `MVNetworkManager#IsOffline`, для проверки наличия компонента в сцене.
Данный компонент переопределяет `NetworkManager#singleton` своим методом `MVNetworkManager#singleton`, что позволяет получать данный компонент внутри других скриптов без поиска по сцене:
```csharp
if (MVNetworkManager.IsOnline())
{
    MVNetworkManager connection = MVNetworkManager.singleton;
}
```
В модуле MainMenu по контракту `MVNetworkManager` всегда присутствует в сцене и проверка `MVNetworkManager.IsOnline()` внутри модуля MainMenu избыточна, по крайней мере, на данный момент.
В остальных же модулях перед получением `MVNetworkManager` требуется осуществлять проверку `MVNetworkManager.IsOnline()`.
 
Помимо своего создания и предоставления доступа к себе, ответственностью данного компонента является предоставление доступа ко всем сетевым событиям.
Данный компонент не обрабатывает события сам, а лишь предоставляет доступ к сетевым событиям другим компонентам при помощи `UnityAction`.

Поскольку `MVNetworkManager` является наследником `NetworkManager`, то он наследует все его конфигурационные свойства.
В добавок к этому, платформе для корректной инициализации нужны дополнительные конфигурационные свойства.
Чтобы не запутаться во всем многообразии опциональных и обязательных конфигураций, все конфигурационные свойства, 
значения которых требуется устанавливать из Unity Editor, вынесены в компонент `NetworkManagerSetups`. 
`NetworkManagerSetups` это, грубо говоря, Builder для `MVNetworkManager`. Сам данный компонент ничего не делает - только передает настройки в конструктор `MVNetworkManager`.

В процессе сетевого взаимодействия необходимо хранить сетевые переменные текущего пользователя. С этой целью `MVNetworkManager` хранит внутри себя `NetworkDataStore`.
`NetworkDataStore` - это хранилище сетевых данных текущей сессии. Поскольку оно хранится внутри `MVNetworkManager` оно доступно в любой онлайн сцене.

Сетевые команды в Mirror так же отправляются через `NetworkManager`. Но писать логику их исполнения внутри `MVNetworkManager` сделает компонент еще менее понятным,
при этом добавит ему лишней ответственности. Написание внешних обработчиков приведет к дублированию кода во множестве скриптов.
С целью изоляции логики сетевых команд было создано расширение `NetworkManagerExtensions`. По сути это набор внешних обработчиков, но С# позволяет вызывать их как внутренние методы `MVNetworkManager`.
```csharp
connection.DisconnectFromNetwork();
```

В платформе используется собственная система спавна игрока и миграции хоста. 
Для реализации этих механик созданы компоненты `NetworkPlayerInstantiationServer` и `NetworkPlayerInstantiationClient`.
`NetworkPlayerInstantiationServer` обрабатывает сетевые события `MVNetworkManager`, которые происходят на Хосте/Сервере.
`NetworkPlayerInstantiationClient` обрабатывает сетевые события `MVNetworkManager`, которые происходят на Клиентах. 
Обратите внимание, что Хост является как сервером, так и клиентом. А значит на нем вызываются события обрабатываемые в обоих компонентах.
*Для понимания последовательности вызова событий, рекомендуется добавить логгирование в методы данных компонентов и по запускать платформу в качестве хоста и клиета*.
`NetworkPlayerInstantiationServer` и `NetworkPlayerInstantiationClient` являются отдельными singleton компонентами, располагающимися на одном объекте с `MVNetworkManager`, но не требующими дополнительных настроек.

## Network Player
Mirror имеет собственное понятие игрока. Сетевой игрок - это идентификатор машины пользователя в сети Mirror.
Основной реализацией сетевого игрока является `NetworkBasePlayer`. 
Его потомком является компонент `NetworkAvatarPlayer`, обрабатывающий сетевого игрока имеющего аватар.
Компоненты `NetworkPlayerInstantiationServer` и `NetworkPlayerInstantiationClient` спавнят в сценах сетевого игрока,
а спавн контроллера и аватара игрока, осуществляет `NetworkAvatarPlayer` на локальной машине каждого из игроков.

## NetworkCore.MirrorNetworking.Synchronization
Mirror предоставляет ряд компонентов синхронизирующих состояние объекта с сервером. Однако эти компоненты не подходят для архитектуры p2p.
Из-за невозможности использования существующий решений синхронизации, были созданы собственные синхронизаторы.
Данные синхронизаторы хранятся в пространстве имен `NetworkCore.MirrorNetworking.Synchronization`.

Данные синхронизаторы должны располагаться на префабах объектов. Они автоматически добавляются в префабы из папки `ApplicationContent` скриптом `NetworkPrefabProcessor`,
если префаб был помечен компонентом `NetworkObject`.

## Offline mode
Сцена должна иметь возможность работы в Онлайн и Офлайн режиме. Однако сетевые компоненты Mirror отключают (`gameObject.enabled = false`) сетевые объекты в офлайн сцене.
Компонент `OfflineModeObject` удаляет сетевые объекты в сцене, если она запущена в офлайн режиме. Таким образом, все объекты остаются активны, но для перехода в онлайн режим необходимо перезапустить сцену.

Компонент `NetworkObjectSwitcher` позволяет включать/отключать объекты сцены, в зависимости от того, находится ли сцена в онлайн режиме.
