# Digital reality lab Software Development Kit
Данный модуль передается сторонним разработчикам. При помощи инструментов из данного модуля, сторонние разработчики могут создавать дополнительный контент для SUAI-Metaverse.
Дополнительный контент реализуемый при помощи данных инструментов автоматически встраивается в исходный проект.

Элементы данного модуля полностью автономны и не имеют зависимостей от SUAI-Metaverse, что обеспечивает возможность их передачи сторонним разработчикам,
без необходимости раскрытия исходного кода всего проекта.

## Требования к проекту сторонних разработчиков
### Версия Unity
SUAI-Metaverse разрабатывается на версии 2021.3.27f1 LTS. Для лучшей совместимости стоит использовать данную версию, либо более поздние версии Unity.

### Text Mesh Pro
SUAI-Metaverse использует Text Mesh Pro.

Добавьте в сцену любой UI объект использующий TextMeshPro, например Button - TextMeshPro. Появится диалоговое окно импорта TextMeshPro.
Выберете пункт Import TMP Essential.

### Event System
Планшет использует Unity UI. Для корректного взаимодействия с планшетом, в сцене должен находиться объект EventSystem.

Для создания EventSystem, создайте любой UI объект в сцене, например Canvas (потом можете удалить данный объект). 
Unity автоматически добавит в сцену объект EventSystem.

### Universal RP
SUAI-Metaverse использует Universal RP. Для разработки дополнительного контента, необходимо что бы ваш проект так же использовал Universal RP, вместо стандартных Unity материалов.

Можно использовать шаблон проекта Unity - "Universal 3D", в котором изначально настроен Universal RP.

Для добавления Universal RP в проект с обычными материалами выполните следующие шаги:
1. Откройте вкладку Window/Package manager;
2. В открывшемся окне, во вкладке "Packages" выберете пункт "Unity Registry";
3. В окошке поиска введите "Universal RP";
4. Установите найденный пакет кнопкой Install и дождитесь перекомпиляции проекта;
5. Закройте окно Package manager;
6. В окне Project щелкните ПКМ. Выберете пункт меню Create/Rendering/URP Asset(With Universal Renderer). Задайте произвольное имя созданному ассету;
7. Откройте вкладку Edit/Project Settings;
8. Выберете пункт Graphics;
9. В свойстве "Scriptable Render Pipeline Settings" укажите ассет созданный в шаге 6.

![image](https://github.com/user-attachments/assets/f32a1d8b-1672-43db-ba71-89b83d21ee93)


Для преобразования уже существующих материалов в Universal RP материалы:
1. Выделите материал в Project;
2. Используйте вкладку Edit/Rendering/Materials/Convert Selected Build-in Materials to URP.

### Именование скриптов
Все скрипты, создаваемые дла работы вашей сцены должны находится внутри `namespace имя_сцены...`

Например, если ваша сцена называется `MyCustomScene`, то скрипты объектов этой сцены должны располагаться в namespace
```csharp
namespace MyCustomScene.SceneObjects.Ball
{
    /// <summary>
    /// <para>Скрипт отскакивающего мячика.</para>
    /// </summary>
    public sealed class BounseBall : MonoBehaviour {
        // Реализация скрипта
    }
}
```

## Создание аватара
На данный момент SUAI-Metaverse позволяет интегрировать только основные аватары пользователя.

### Основной аватар пользователя
Основной аватар пользователя - это аватар, который пользователь выбирает при входе в систему. При попадании в новую комнату пользователь всегда будет представлен своим основным аватаром.

Данный аватары должны иметь аниматор с `Apply Root Motion == ture`, `Update Mode == Nurmal`, `Culling Mode == Cull Update Transforms` и аватар с Humanoid скелетом.
Для создания аватара, удовлетворяющего данным критериям, выполните следующие действия:
1. Получите FBX аватара с Humanoid скелетом;
2. Импортируйте FBX в Unity;
3. Откройте импортированный файл в Инспекторе Unity (кликните по импортированному файлу);
4. В инспекторе перейдите на вкладку Rig;
5. В свойстве "Animation Type" укажите значение Humanoid;
6. Нажмите Apply.

![image](https://github.com/user-attachments/assets/972a6eb4-0229-47dc-9132-c3998200be09)


Для проверки работоспособности импортированного FBX аватара, добавьте в сцену `Assets/LDR_SUAI_Metaverse_SDK/Prefabs/Player/SDK_PCPlayer.prefab`
и в компоненте `HumanoidPlayerAvatar` укажите ваш FBX в свойстве `_playerAvatar`. Отключите в сцене MainCamera. Запустите сцену.
`SDK_PCPlayer.prefab` заспавнит в сцене ваш аватар, перенесет основную камеру на уровень глаз аватара и добавит аватару анимацию ходьбы.
Если при запуске не произошло ошибок, камера переместилась на уровень глаз и при ходьбе аватар воспроизводит анимацию,
значит созданный FBX подходит для интеграции в SUAI-Metaverse. 

Если модель не соответствует ожидаемому размеру - вы можете изменить Scale Factor самой модели, либо создать prefab и настроить scale prefab-а.

Для изменения scale самой модели, выберете во вкладке Project FBX файл модели. В инспекторе откройте вкладку Model.
Измените параметр Scale Factor. Нажмите Apply.

Создав оригинальный prefab модели измените в его компоненте Transform свойство scale. 
В свойство `_playerAvatar` передавайте prefab, вместо FBX.

FBX модель аватара, текстуры, материалы, изображение аватара (.png/.jpg) и prefab(если есть) должны находиться в одной папке,
что бы ее можно было свободно перенести в исходный проект без нарушения зависимостей. Изображение аватара должно иметь имя соответствующее шаблону: "*имя_аватара*Icon".

Сервис Ready Player Me сразу предоставляет аватары с Humanoid скелетом, но в формате `.glb`.
Необходимо конвертировать `.glb` файл в `.fbx`, например через blender,
а затем в импортированном FBX на вкладке инспектора Materials указать оригинальные материалы из `.glb`.

Если вы разработали собственную модель без скелета, то сервис [mixamo](https://www.mixamo.com/#/) позволит добавить Humanoid скелет и получить `.fbx` файл.
Однако будьте внимательны. Mixamo может удалить с модели все текстуры. 
После добавления Humanoid скелета импортируйте модель в Unity и восстановите все текстуры в материалах модели, если требуется.

Примеры аватаров совместимых с метавселенной находятся в `Assets/LDR_SUAI_Metaverse_SDK/Examples/CustomAvatars`. 
Папки с аватарами содержат все необходимые зависимости и изображение аватара с корректным именем.

## Создание сцены
Сцена должна храниться в отдельной папке. В этой же папке должно храниться изображение сцены. 
Изображение должно иметь имя соответствующее шаблону: "*имя_сцены*Icon". 

В этой папке должны быть папки со всеми зависимостями сцены. 
Если в сцене есть какая-то модель, то данная модель должна храниться в папке со сценой или в подпапках папки со сценой. 
Если в сцене используется какой-то скрипт - то он должен храниться в папке со сценой или в подпапках папки со сценой.
Это нужно, для того, что бы папку с ценой можно было свободно перенести в исходный проект без нарушения зависимостей.

Пример организации хранения зависимостей сцены можно посмотреть в `LDR_SUAI_Metaverse_SDK/Examples/CustomScene/`.

После создания сцены:
1. Добавьте в сцену EventSystem. Для создания EventSystem, создайте любой UI объект в сцене, например Canvas (потом можете удалить данный объект). Unity автоматически добавит в сцену объект EventSystem;
2. Удалите из сцены MainCamera;
3. Добавьте на сцену точки спавна игроков. Точки спавна находятся в `LDR_SUAI_Metaverse_SDK/Prefabs/SceneLogic/SpawnPoint/`;
4. Если вы использовали для отладки префаб игрока, уберите его - точки спавна будут сами спавнить игрока в сцене.

### Создание страницы комнаты в планшете
Какие-то интерактивности комнаты могут управляться с планшета. 

Пример такого управления есть в `LDR_SUAI_Metaverse_SDK/Examples/CustomScene/CustomScene.unity`. 
В данной сцене вы можете открыть планшет кнопкой `F2`. 
Перейти во вкладку "Управление сценой". В данной вкладке 2 странички, управляющие разными стендами. 
На вкладке 1 можно запустить/остановить анимацию паука на стенде. На вкладке 2 можно установить свое имя на стенд.

Контент вкладки планшета "Управление сценой" предоставляется текущей комнатой. 
В комнате находится компонент `UITabletRoomContentSupplier`, в свойстве которого указан префаб UI. 
Данный префаб будет создан в планшете игрока, при попадании в комнату. 
Для создания такого префаба воспользуйтесь инструментом `LDR_SUAI_Metaverse_SDK/Tools/TabletRoomContentCreator/CreateTabletRoomUITemplate.unity`.

Скопируйте `CreateTabletRoomUITemplate.unity` через Ctrl + D, чтобы сохранить исходный инструмент - работайте в копии сцены.

В данной сцене представлена упрощенная модель планшета. Если вы запустите сцену, 
то серый экран "Разрабатываемый UI" будет заменен зеленым экраном "Готовый UI из сцены".

Создайте свой UI внутри объекта `RoomContentTablet/UI/MainWindow/Content/RoomContent/DevelopedСontent/`.
В данной сцене создается только UI логика. Взаимодействие с объектами сцены будет настроено внутри самой сцены.
Разрабатывайте UI таким образом, чтобы объектам сцены не нужно было на него ссылаться
т.к. в игре будет использоваться не конкретный экземпляр объекта, а из данного объекта будут создаваться его копии. 
Если объекты сцены будут ссылаться на ваш UI, то они потеряют ссылку на копии данного UI, полученные игроками.

После создания UI - переименуйте DevelopedСontent в "*имя_сцены*RoomContent". Сохраните данный объект как префаб в папке вашей сцены.
Чтобы убедится в его работоспособности - добавьте данный префаб, как потомка `SceneSettings/Tablet/`. 
А в объекте `SceneSettings/Tablet`, в компоненте `UITabletRoomContentSupplier` укажите данный экземпляр в поле `Content`.
При запуске сцены, серый экран "Разрабатываемый UI" должен быть заменен на ваш UI. 
Модифицируйте ваш префаб, пока не будете довольны результатом.

После создания префаба вашего UI, перейдите в создаваемую вами сцену.
Добавьте в сцену компонент `LDR_SUAI_Metaverse_SDK/Components/Tablet/UITabletRoomContentSupplier`.
Добавьте в сцену префаб вашего UI. Укажите экземпляр вашего префаба в сцене в поле `Content` компонента `UITabletRoomContentSupplier`.
Далее донастройте экземпляр вашего UI, указав ему ссылки на объекты сцены, которые он контролирует.

## Создание интерактивного объекта
Игрок взаимодействует с объектами сцены при помощи компонента `InteractorPC`, который находится на игроке. 
Если вы запустите сцену с игроком, то в Scene View увидите, что от игрока идет луч. Это луч взаимодействия из компонента `InteractorPC`.
Луч соприкасается с объектами, у которых есть коллайдер. Если луч красный, значит он не соприкасается ни с какими объектами. 
Если луч зеленый, значит он соприкасается с не интерактивными объектами. Если луч розовый, значит он соприкасается с интерактивным объектом. 
Когда луч соприкасается с интерактивным объектом, можно нажать или зажать `F`, для взаимодействия.
Так же если луч соприкасается с объектом, у которого есть подсказка, то подсказка будет отображаться тому игроку, луч которого соприкасается с объектом.

> Для создания интерактивного объекта напишите скрипт компонента, реализующий интерфейс `IInteractable`. 

У данного интерфейса один обязательный метод - `Interact()`.
В реализации данного метода опишите логику, выполняемую объектом при взаимодействии игрока с ним. 
Пример реализации данного метода - `ExampleAnimateOtherObjectButton`. 
Его работу можно посмотреть в сцене `LDR_SUAI_Metaverse_SDK/Examples/CustomScene/CustomScene.unity`, на стенде с кнопкой и пауком. 
По нажатию кнопки воспроизведется анимация паука. 

Если необходимо реализовать длительное взаимодействие через зажатие клавиши взаимодействия, то необходимо переопределить свойство:
```csharp
public bool AllowHoldInteraction => true;
```
После переопределения данного свойства, если игрок зажимает `F`, то каждый `FixedUpdate` (0.02 секунды) игрок будет вызывать метод `Interact()` у данного объекта.
Пример реализации зажатия кнопки - `PressButtonAnimation`. В сцене `LDR_SUAI_Metaverse_SDK/Examples/CustomScene/CustomScene.unity`
есть стенд, передвигающий кубик влево/вправо через зажатие кнопки.

Если при взаимодействии нужно получить информацию об игроке, вызвавшем взаимодействие, то реализуйте метод `Interact(GameObject owner)`.
<u>Внутри данного метода обязательно осуществите вызов метода `Interact()`, даже если в вашем скрипте данный метод ничего не делает</u>.
Входным параметром данного метода будет передан аватар игрока, осуществляющий взаимодействие. 
Пример реализации - `ExampleAvatarAnimationButton`. Данный скрипт воспроизводит анимацию аватара по нажатию на кнопку. 
В сцене `LDR_SUAI_Metaverse_SDK/Examples/CustomScene/CustomScene.unity` есть стенд с кнопкой, по нажатию на которую аватар воспроизводит цепочку анимаций.

Иногда необходимо реализовать взаимодействие с привязкой - когда первое взаимодействие привязывает объект, а повторное взаимодействие отвязывает.
В этом случае логику привязки объекта реализуйте в методе `Interact()`, а для реализации логики отвязки реализуйте метод `StopInteraction()`.
Пример взаимодействия с привязкой - `GrabableTransform`. В сцене `LDR_SUAI_Metaverse_SDK/Examples/CustomScene/CustomScene.unity`
есть стенд, на котором вы можете взять кубик первым нажатием `F`, а повторным нажатием отпустить его. 

При взаимодействии с привязкой вы возможно захотите запретить другим пользователям взаимодействовать с объектом, пока он привязан к текущему пользователю.
Для этого необходимо реализовать [право владения данным объектом](#создание-объекта-с-правом-владения). 

Если взаимодействие можно форсировано прервать извне (отобрать у игрока предмет с которым он взаимодействует), то реализуйте метод `ResetInteraction()`.

Для реализации подсказки взаимодействия, скрипт должен реализовывать интерфейс `ITooltip`. 
В данном интерфейсе 2 обязательных метода - `ShowTooltip` и `HideTooltip`. В методе `ShowTooltip` опишите логику появления подсказки,
а в методе `HideTooltip` логику исчезновения подсказки. Пример реализации - `ButtonTooltip`. 
Практически все интерактивные объекты сцены `LDR_SUAI_Metaverse_SDK/Examples/CustomScene/CustomScene.unity` реализуют различные подсказки,
как при помощи UI, так и при помощи вспомогательных объектов.

## Добавление анимации аватару
При некоторых взаимодействиях аватар игрока должен осуществлять анимацию. Например, если вы реализуете книжный шкаф и вы хотите, 
что бы аватар игрока при взаимодействии со шкафом воспроизводил анимацию чтения книги. Анимацию нельзя помещать в аниматор игрока,
потому что книжный шкаф будет только в вашей сцене, а в других сценах данная анимация не нужна. 
Поэтому анимацию чтения книги Humanoid аватаром должен хранить сам шкаф. 
А при взаимодействии аватара со шкафом, шкаф получает аниматор аватара и через него воспроизводит хранимые анимации.

Если вы реализуете интерактивный объект, при взаимодействии с которым, аватар игрока должен воспроизвести анимацию, то воспользуйтесь методом:
```csharp
// Список анимаций, которые должен воспроизветси аватар игрока
List<AnimationClip> animations = new List<AnimationClip>();

// ...

if (playerAvatar.TryGetComponent(out Animator avatarAnimator))
{
    // При помощи аниматора avatarAnimator воспроизвести цепочку анимаций animations 
    StartCoroutine(AnimationUtils.PlayExternalAnimation(avatarAnimator, animations));
}
```
Пример реализации - `ExampleAvatarAnimationButton`. Данный скрипт воспроизводит анимацию аватара по нажатию на кнопку.
В сцене `LDR_SUAI_Metaverse_SDK/Examples/CustomScene/CustomScene.unity` есть стенд с кнопкой, по нажатию на которую аватар воспроизводит цепочку анимаций.

## Создание объекта с синхронизацией анимации
> Если объект должен синхронизировать свое поведение с сетью через сообщение сети данных о себе,
то необходимо создать из объекта префаб. Добавить на данный префаб компонент `LDR_SUAI_Metaverse_SDK/Components/NetworkSync/NetworkObject`.

Если анимация объекта воспроизводится независимо от действий игроков, то данную анимацию синхронизировать не нужно.
У каждого игрока в сцене она будет воспроизводиться по одинаковой логике, а значит будет одинакова у всех игроков.

При синхронизации анимации, объект должен передавать id воспроизводимой в данный момент анимации другим игрокам.
Если вы хотите, что бы анимация id воспроизводимой анимации отправлялся в сеть, 
то установите у компонента `NetworkObject` checkbox `Animated Object`. 
В сцене `LDR_SUAI_Metaverse_SDK/Examples/CustomScene/CustomScene.unity` практически все кнопки синхронизируют анимацию своего нажатия.

## Создание объекта с синхронизацией положения
> Если объект должен синхронизировать свое поведение с сетью через сообщение сети данных о себе,
то необходимо создать из объекта префаб. Добавить на данный префаб компонент `LDR_SUAI_Metaverse_SDK/Components/NetworkSync/NetworkObject`.

Если положение объекта вычисляется локально, независимо от сетевых действий игроков, то положение данного объекта синхронизировать не нужно.
У каждого игрока в сцене положение будет корректно вычисляться локально, а значит будет одинаково у всех. 

Положение объектов может изменяться через изменение `Transform`, либо через взаимодействие с `RigidBody` объекта.

Если положение объекта вычисляется через изменение `Transform`, то установите у компонента `NetworkObject` checkbox `Transform Object`.
В сцене `LDR_SUAI_Metaverse_SDK/Examples/CustomScene/CustomScene.unity` есть стенды с кубами, которые передвигаются вправо/влево через нажатие кнопок.
Данные кубы синхронизируют свое положение с сервером.

Если положение объекта вычисляется через взаимодействие с `RigidBody` объекта, то установите у компонента `NetworkObject` checkbox `Physic Object`.
В сцене `LDR_SUAI_Metaverse_SDK/Examples/CustomScene/CustomScene.unity` есть мячик с `RigidBody`, который синхронизирует свое положение с сервером.

## Создание UI Текста с синхронизируемым содержимым
> Если объект должен синхронизировать свое поведение с сетью через сообщение сети данных о себе,
то необходимо создать из объекта префаб. Добавить на данный префаб компонент `LDR_SUAI_Metaverse_SDK/Components/NetworkSync/NetworkObject`.

Если в вашей сцене есть `Canvas`, содержащий `TextMeshPro - Text`, содержимое которого должно быть синхронизировано у всех игроков,
то на данный `Canvas` добавьте компонент `LDR_SUAI_Metaverse_SDK/Components/NetworkSync/NetworkObject` и установите у него checkbox `Canvas`.
В этом случае все `TextMeshPro - Text` данного `Canvas` будут синхронизированы с сетью. 
Если по каким-то причинам вы хотите, что бы только часть `TextMeshPro - Text` была синхронизирована, а другая часть у игроков различалась,
То вынесете не синхронизируемую часть на отдельный `Canvas` внутри синхронизируемого. Все компоненты внутреннего `Canvas` не будут синхронизироваться.

В сцене `LDR_SUAI_Metaverse_SDK/Examples/CustomScene/CustomScene.unity` при помощи планшета можно установить на стенд имя пользователя.
Откройте планшет кнопкой `F2`. Перейти во вкладку "Управление сценой". Перейдите на вкладку 2. Установите имя пользователя.
`Canvas`, в который устанавливается имя вашего пользователя, синхронизирует свои тексты с сетью.

## Создание объекта с правом владения
> Если объект должен синхронизировать свое поведение с сетью через сообщение сети данных о себе,
то необходимо создать из объекта префаб. Добавить на данный префаб компонент `LDR_SUAI_Metaverse_SDK/Components/NetworkSync/NetworkObject`.

Некоторыми объектами одновременно может владеть лишь один игрок. Такие объекты должны иметь компонент, проверяющий доступ к объекту - `IInteractionAccess`.
Получить данный компонент можно при помощи метода:
```csharp
IInteractionAccess access = NetworkEnvironment.GetInteractionAccessor(gameObject);
```

Через данный компонент проверяется возможность взаимодействия с объектом. 
Метод `access.IsInteractionAllowed()` вернет `false`, если объектом кто-то владеет в данный момент.
При помощи метода `access.HasInteractionControl(player)` мы можем проверить, является ли `player` тем GameObject, что в данный момент владеет объектом.
Если `access.IsInteractionAllowed() == true`, то мы можем запросить владение объектом для себя, при помощи метода `access.AcquireControl(player)`.
Тогда мы станем владельцем данного объекта и будем им до тех пор, пока не отключимся или не вызовем метод `access.ReleaseControl()`.

Однако недостаточно просто в скрипте вызвать `NetworkEnvironment#GetInteractionAccessor` и реализовать логику владения. 
Необходимо так же в компоненте `LDR_SUAI_Metaverse_SDK/Components/NetworkSync/NetworkObject` установить checkbox `Can Be Owned`.

В сцене `LDR_SUAI_Metaverse_SDK/Examples/CustomScene/CustomScene.unity` кубы, 
которые можно перетаскивать в пространстве имеют компонент `GrabableTransform` или `GrabableWithPhysics`. Если куб перетаскивает один игрок, 
другой игрок не может взаимодействовать с кубом. Так же в данной сцене можно при помощи планшета установить на стенд имя пользователя.
Откройте планшет кнопкой `F2`. Перейти во вкладку "Управление сценой". Перейдите на вкладку 2. 
Перед тем как установить имя пользователя, вы должны запросить владение у `UIExampleChangeText`. 
Пока данным компонентом владеет один игрок, второй не сможет установить в него имя пользователя.

## Получение сетевых данных
### Время жизни комнаты
Не все объекты должны передавать свое состояние на сервер. Часть объектов выполняет локальные вычисления у каждого конкретного пользователя.
Но синхронизируются такие объекты по времени сервера. Например, часы. Не нужно синхронизировать положение стрелок у всех пользователей.
Достаточно получить время комнаты и установить значение стрелок согласно этому времени. Это касается не только часов. 
Светофор, солнце, работа магазинов... Если состояние объекта зависит от времени, то не нужно синхронизировать все состояние, 
достаточно в момент инициализации сетевой комнаты получить ее текущее время. Затем рассчитать текущее состояние объекта, относительно времени в комнате.

Загрузка сцены, отрисовка первого кадра, появление объекта в сцене и инициализация сетевой комнаты это разные и не связанные друг с другом события.
Поэтому <u>нельзя</u> получать время сетевой комнаты в `Start`, `OnEnable` или при загрузке локальной сцены. 
Используйте `NetworkEnvironment#WhenConnectToRoom`. Данный метод входным параметром принимает метод, который будет вызван при инициализации сетевой комнаты.
Узнать была ли инициализирована сетевая комната можно при помощи метода `NetworkEnvironment#IsConnectedToRoom`.

> Для получения времени, прошедшего с момента создания сетевой комнаты используется метод `NetworkEnvironment#GetRoomLifetime`

Пример синхронизации локальных вычислений со временем жизни комнаты - `ExampleRoomLocalSyncTimer`. 
В сцене `LDR_SUAI_Metaverse_SDK/Examples/CustomScene/CustomScene.unity` есть стенд с таймером, отображающим текущее время жизни комнаты.
Оно будет одинаково у всех игроков, не важно насколько поздно они подключились. Однако вычисление времени производится локально на машине каждого игрока.
На стенде 3 кнопки. Первая остановит таймер. Тогда у локального игрока таймер остановится, а у остальных продолжит идти. Получится рассинхронизация. Вторая кнопка возобновит таймер.
Поскольку вычисления локальные, то таймер продолжит отсчет с того места на котором остановился. Таким образом, таймер локального игрока будет отставать от таймера остальных игроков.
Однако по нажатию третьей кнопки, таймер установит текущее значение из результата метода `NetworkEnvironment#GetRoomLifetime` таким образом, догнав таймеры остальных игроков,
а затем продолжит локальный отсчет. Значение таймера будет синхронизировано, несмотря на то что `Canvas` отображающий текущее время не синхронизирован с сетью.

### Имя текущего пользователя
Имя текущего пользователя можно получить при помощи метода `NetworkEnvironment#GetUsername`.
